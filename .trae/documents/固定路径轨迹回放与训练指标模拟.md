**目标**

* 在 UE×AirSim 场景中，后端按照预设固定路径（多无人机各自的航点序列）进行轨迹回放，模拟“已训练好的策略”穿越复杂电磁干扰区域到达终点的效果。

* 同步采集并输出一套接近 RL 训练的核心指标（reward\_sum、success、collision/oob、dist\_to\_goal、jammer\_power 等），用于展示与评估。

**实现内容**

* 新增运行器：runners/trajectory\_playback.py（不改动并行环境），直接使用 AirSim 适配层控制无人机沿航点移动。

* 新增配置块：在 default.yaml 增加 trajectory 配置（每个 agent 的 waypoints、速度/步长、是否按朝向追踪 yaw、CSV 输出开关与路径）。

* 指标采集：复用 JammerLocator（HTTP /jammers, /jammer\_power）与 RewardComposer，按现有契约计算“进步奖励+干扰惩罚+终止/步惩罚”等；记录结构化 JSON 日志与 CSV。

**技术细节**

* 轨迹表示：trajectory.waypoints：{Drone1:\[\[x,y,z],...], Drone2:...}；支持从 spawn\_points 自动追加首航点；步进 dt 取自 EnvConfig（可被 trajectory.dt 覆盖）。

* 运动控制：

  * 每步根据当前位置到下一航点的向量，计算目标速度 v=clip(v\_max)，yaw\_rate 基于朝向变化（可选按航点方向追踪）。

  * 调用 AirSimClient.move\_velocity(...).join() 保证 dt 一致；到达阈值（goal\_radius）后切换到下一航点。

* 终止条件：到达最终航点或发生 collision/oob 或最大步数；与 TerminationChecker 一致。

* 干扰采样：每步通过 JammerLocator.nearest\_power(pos, step) 获取功率；记录 dB（\_to\_db）与原值；若 HTTP 不可用则回退 0。

* 奖励计算：使用 RewardComposer（mode=power 或 distance），传入 prev\_goal\_dist、dist\_to\_goal、功率/距离及状态标志，累积 reward\_sum。

**数据与日志**

* JSON 日志：沿用 RLLogger（队列+轮转），输出 step\_before/step\_after、\[INTERFERENCE]、policy\_update（占位）。

* CSV 输出：trajectory\_demo.csv（列：episode, step, agent, x,y,z, dist\_to\_goal, jammer\_power, reward, collided, oob, reached\_goal, timestamp）。

* 汇总指标：每架无人机的 reward\_sum、episode\_len、avg\_jammer\_power(dB/raw)、min\_dist\_to\_goal、是否成功；全局 success\_rate、collision\_rate。

**运行方法**

* 连通 UE HTTP 后：PYTHONPATH=src python -m airsim\_multi\_rl.runners.trajectory\_playback --episodes 1 --steps 500

* 可通过环境变量/CLI 覆盖 YAML（如 trajectory.dt、速度、CSV 路径）；默认读取 default.yaml。

**最小单测**

* 在 tests/ 中新增测试：使用 DummyClient 验证 CSV 写出（列齐全）、奖励计算调用、轨迹推进逻辑（到达阈值向下一航点）。

**风险与保障**

* 性能：控制循环仅调用 move\_velocity 与最近功率查询；HTTP 步频由 query\_every\_n\_steps 控制。

* 稳定性：所有 Async 命令 join；异常捕获并降级日志，不中断整体回放。

* 兼容性：若 HTTP 不通或未返回 Jammer 名单，功率置 0 但轨迹仍回放；RewardComposer 自动回退 distance 模式可选。
